## 概述

知识库是睿阁的核心数据组织单元。所有需要被智能体检索和引用的知识内容——无论是企业文档、FAQ 问答对，还是外部数据源同步的资料——都以知识库为单位进行管理、索引和检索。

读完本文你将了解：

- 睿阁支持哪几种知识库类型，各自适合什么场景。
- 索引策略（RAG 检索、Wiki 知识库）的区别与适用场景。
- 文档进入知识库后经历了怎样的分块、向量化和检索过程。
- AI 问题生成、知识图谱等高级能力的工作原理。

## 前置条件

- 已登录睿阁并进入主工作区。
- 建议先阅读 [创建首个知识库](/zh/tutorials/01-first-knowledge-base) 了解端到端操作流程，本文重在解释概念模型。

## 知识库类型

睿阁支持两种知识库类型，创建时需选择其一，创建后不可更改：

| 类型 | 说明 | 典型场景 |
| --- | --- | --- |
| 文档库 | 上传 PDF、Word、Excel、PPT、图片、音频、Markdown、CSV、JSON 等文件，系统自动解析、分块并建立索引 | 企业内部文档、产品手册、研究报告、合同文本 |
| FAQ 库 | 以"标准问 + 相似问 + 答案"的问答对形式组织知识，精确匹配用户提问 | 客服常见问题、产品 FAQ、政策解答 |

> 提示：FAQ 库的检索精度通常高于文档库，因为问答对的语义更加明确。如果您的知识内容可以整理为问答对形式，建议优先使用 FAQ 库。

### 文档库支持的文件格式

| 文件类型 | 扩展名 | 说明 |
| --- | --- | --- |
| PDF 文档 | .pdf | 支持文本型和扫描件（需配置多模态模型） |
| Word 文档 | .docx / .doc | 完整解析文本和表格 |
| 演示文稿 | .pptx / .ppt | 提取文本内容 |
| Excel 表格 | .xlsx / .xls | 结构化数据，支持数据分析工具 |
| CSV 文件 | .csv | 结构化数据 |
| Markdown | .md | 轻量标记语言 |
| 纯文本 | .txt | 纯文本格式 |
| JSON 文件 | .json | 结构化数据 |
| 图片 | .jpg / .jpeg / .png / .gif | 需配置多模态视觉模型 |
| 音频 | .mp3 / .wav / .m4a / .flac / .ogg | 需配置 ASR 语音识别模型 |

### FAQ 库的索引方式

FAQ 库提供两种索引维度，可灵活组合：

**索引方式**（控制向量索引中是否包含答案内容）：

| 选项 | 说明 | 适用场景 |
| --- | --- | --- |
| 仅标准问/相似问 | 索引中只包含问题文本，语义匹配更精确 | FAQ 数量充足，追求检索精度 |
| 标准问+答案 | 索引中同时包含问题和答案，召回率更高但可能引入噪音 | FAQ 数量少，答案中有独特关键词 |

**问题索引方式**（控制标准问和相似问的索引结构）：

| 选项 | 说明 | 适用场景 |
| --- | --- | --- |
| 合并索引 | 标准问和所有相似问拼成 1 条向量索引，节省存储空间 | FAQ 数量多，想节省存储 |
| 分别索引 | 标准问和每个相似问各自生成独立索引，检索更精确 | 追求检索精度，支持增量更新 |

## 索引策略

文档库创建时需要选择索引策略，决定知识库的检索能力和内容组织方式：

### RAG 检索

RAG（Retrieval-Augmented Generation）检索是睿阁的核心检索能力，通过**向量检索 + 关键词检索**的混合策略，在海量文档中精准找到与用户问题最相关的内容。

- **向量检索**（默认开启）：基于语义相似度的深度匹配，能理解问题含义而非依赖字面关键词。
- **关键词检索**（与向量检索联动）：基于精确关键词的快速匹配，适合查找特定术语、产品名称、错误代码等。

两种检索策略并行执行后合并结果，再通过 Rerank 重排序模型进行最终排序，确保返回最相关的内容。

### Wiki 知识库

Wiki 知识库将文档内容提炼为结构化的知识页面，以百科式的方式组织信息。适合需要全局概览、跨文档关联和导航式阅读的场景。

Wiki 索引启用后可配置：

| 配置项 | 说明 |
| --- | --- |
| 提取粒度 | 聚焦 / 标准 / 详尽，控制知识页面的信息密度 |
| Wiki 内容生成要求 | 自定义 Wiki 页面的生成风格和重点 |
| Wiki 提取重点 | 指定需要重点关注的知识领域 |

> 提示：RAG 检索和 Wiki 知识库可以同时启用，智能体可以同时利用两种检索方式获取信息。详情参见 [智能体](/zh/concepts/02-agent)。

## 分块原理

文档上传后，系统会自动将长文档切分为更小的文本片段（称为"分块"或"chunk"），每个分块独立建立索引。分块质量直接影响检索效果。

### 分块策略

| 策略 | 说明 |
| --- | --- |
| 自动 | 系统根据文档结构自动选择最佳切分方式（默认） |
| 按标题切分 | 依据文档中的标题层级进行切分，适合结构清晰的文档 |
| 结构感知 | 分析文档的版面结构（段落、列表、表格等），智能切分 |
| 按长度切分 | 按固定字符长度切分，适合无明显结构的纯文本 |

### 分块参数

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| 分块大小 | 512 字符 | 单个分块的最大字符数 |
| 分块重叠 | 80 字符 | 相邻分块之间的重叠字符数，确保上下文连贯 |
| 分隔符 | 双换行、单换行、句号等 | 用于切分的标点符号，可多选 |

### 父子分块

父子分块是睿阁的一项重要能力（默认开启），它在普通分块的基础上建立了两层结构：

- **子块**（默认 384 字符）：用于向量检索的最小单元，粒度更细、匹配更精确。
- **父块**（默认 4096 字符）：包含更完整的上下文信息，检索到子块后会自动关联其父块，为模型提供更丰富的背景。

父子分块的工作流程：

1. 文档先按父块大小切分为大段落。
2. 每个父块再按子块大小切分为更小的片段。
3. 检索时以子块为单位进行匹配，命中后自动携带父块的完整上下文。

> 提示：父子分块能显著提升检索质量——子块负责精准定位，父块负责提供完整上下文。建议保持默认开启。

## 向量检索原理

向量检索是睿阁 RAG 检索的核心，其工作流程如下：

```mermaid
flowchart LR
    A[用户问题] --> B[Embedding 模型<br/>文本→向量]
    B --> C[向量数据库<br/>相似度匹配]
    C --> D[Top-K 结果]
    D --> E[Rerank 重排序]
    E --> F[最终检索结果]

    style A fill:#e0f2fe,stroke:#0284c7
    style F fill:#dcfce7,stroke:#16a34a
```

1. **文本向量化**：Embedding 模型将文本（用户问题和知识库分块）转换为高维向量。
2. **相似度匹配**：在向量数据库中，计算用户问题向量与所有分块向量的距离，找到最相似的 Top-K 个分块。
3. **Rerank 重排序**：使用 Rerank 模型对候选结果进行更精细的相关性评分，过滤低质量结果，输出最终排序。

### 关键词检索

关键词检索基于精确文本匹配，适合查找包含特定术语的内容。它与向量检索并行执行，两者结果合并后再统一排序。

关键词检索的阈值控制了最低匹配分数（默认 0.3），分数低于阈值的结果会被过滤。

### Rerank 重排序

Rerank 模型对向量检索和关键词检索的合并结果进行二次排序。它使用更精细的语义理解能力，评估每个结果与用户问题的实际相关性，并给出一个相关性分数。

Rerank 配置参数：

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| 重排数量 | 5 | 重排序后进入答案生成的文档数量 |
| 重排阈值 | 0.5 | 低于此分数的结果被过滤 |

> 注意：Rerank 模型需要在模型配置中单独配置。未配置 Rerank 模型时，系统将跳过重排序步骤，直接使用向量检索和关键词检索的合并结果。

## AI 问题生成

AI 问题生成是睿阁的一项默认开启的高级能力。在文档解析阶段，系统会使用大语言模型为每个文本分块自动生成若干问题（默认 3 个/块）。

生成的问题会被单独建立索引。当用户提问时，如果问题与某个自动生成的问题高度相似，系统可以直接命中对应的分块，从而显著提升召回率。

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| 每块生成问题数 | 3 个 | 范围 1-10，数量越多召回率越高但处理时间更长 |
| 问题生成要求 | 无 | 可指定目标受众或问题风格，如"生成面向技术人员的深层问题" |

> 提示：AI 问题生成会增加文档入库时的处理时间和 LLM 调用成本，但对检索效果提升明显。建议保持默认开启。

## 知识图谱

知识图谱通过 LLM 从文档中自动提取实体和关系，构建结构化的知识网络。图谱数据可用于扩展检索上下文——通过实体间关系找到相关分块，弥补纯向量检索在跨文档关联上的不足。

知识图谱的工作流程：

1. 文档上传后，系统根据配置的提取参数调用 LLM 提取实体和关系。
2. 提取结果与预定义的种子实体合并去重。
3. 使用 PMI（点互信息）和强度加权计算关系权重。
4. 构建分块间关系图，检索时可通过实体关系扩展上下文。

> 注意：知识图谱功能需要系统已启用图数据库（Neo4j），且需要管理员权限进行配置。启用后会显著增加文档入库处理时间和 LLM 调用成本。

## 数据源同步

知识库支持连接外部数据源，自动将外部平台的文档同步到知识库中。支持的数据源包括：

| 数据源 | 说明 |
| --- | --- |
| 飞书 | 飞书文档、电子表格、多维表格 |
| Notion | Notion 页面和数据库 |
| Confluence | Confluence 页面 |
| 语雀 | 语雀知识库 |
| GitHub | GitHub 仓库文档 |
| 钉钉 | 钉钉文档 |
| Web Crawler | 网站爬虫（Sitemap） |
| Email | 邮件（IMAP） |
| RSS | RSS/Atom 订阅源 |

数据源同步支持增量同步和全量同步，可配置定时同步计划（Cron 表达式）。

> 提示：数据源管理在知识库创建后才能配置，属于高级配置中的「存储与数据」分区。

## 常见问题

**Q1：文档库和 FAQ 库可以互相转换吗？** 不可以。知识库类型在创建时确定后不可更改。如果需要更换类型，请新建一个知识库并重新导入内容。

**Q2：文档入库后多久可以检索？** 取决于文档大小和配置的功能。普通文档通常在几分钟内完成解析和索引；如果启用了 AI 问题生成、知识图谱等高级功能，处理时间会更长。

**Q3：大表格被强制分割怎么办？** 当内容超过最大分块大小时会被强制分割。可以尝试调大分块大小参数。注意系统对超大表格有硬编码的最大保护尺寸限制。

**Q4：扫描件 PDF 无法解析怎么办？** 扫描件 PDF（图片型）需要配置多模态视觉模型（VLM）才能提取文字。请在知识库设置中开启多模态功能并配置 VLM 模型。

**Q5：CSV 文件解析后显示乱码怎么办？** 请使用 UTF-8 + BOM 编码方式保存 CSV 文件后重新上传。
