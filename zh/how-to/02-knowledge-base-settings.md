## 概述

知识库高级设置提供了对知识库的详细配置能力，涵盖模型选择、索引策略、解析引擎、分块策略、知识图谱、存储管理等方面。合理配置这些选项可以显著提升知识库的检索精度和回答质量。

本文详细介绍知识库设置弹窗中每个配置项的含义和使用建议。

---

## 前置条件

- 已登录睿阁，且当前账号具备知识库管理权限。
- 已创建或正在创建一个知识库（参见 [知识库管理](/zh/how-to/01-knowledge-base)）。
- 如需使用特定解析引擎（如 MinerU、PaddleOCR-VL），需确认系统设置中已配置对应服务的连接信息。

---

## 界面结构

知识库设置界面为模态弹窗，整体分为三个区域：

| 区域 | 说明 |
| --- | --- |
| 左侧导航栏 | 分为顶级菜单（基本信息、共享管理）和可折叠的高级配置组 |
| 右侧内容区 | 显示当前选中导航项的配置表单 |
| 底部操作栏 | 包含「取消」和「创建」/「保存」按钮 |

**左侧导航结构**：

- **顶级菜单**：基本信息、共享管理
- **高级配置**（可折叠，分三个子组）：
  - 核心配置：模型配置、向量存储、FAQ 配置（仅问答类型显示）
  - 索引与解析（仅文档类型显示）：解析引擎、多模态配置、音频处理、分块设置、知识图谱、高级设置
  - 存储与数据（仅文档类型显示）：存储引擎、数据源管理（仅编辑模式显示）

## 操作步骤

### 1. 基本信息

基本信息是创建知识库时的必填项，定义知识库的类型和核心标识。

| 配置项 | 是否必填 | 说明 |
| --- | --- | --- |
| 知识库 ID | 只读 | 仅编辑模式显示，带复制按钮 |
| 知识库类型 | **是** | 文档 或 问答（创建后不可修改） |
| 索引策略 | **是** | RAG 检索 或 Wiki 知识库（仅文档类型，创建后若已有文件则锁定） |
| 知识库名称 | **是** | 最多 50 字 |
| 知识库描述 | 否 | 最多 200 字 |

#### 索引策略详解

| 策略 | 说明 | 开关配置 |
| --- | --- | --- |
| RAG 检索 | 基于向量检索 + 关键词检索的混合检索模式 | 向量检索开关（默认开启，同时启用关键词检索） |
| Wiki 知识库 | 将文档结构化为 Wiki 页面，支持图谱跳转和深度引用 | Wiki 索引开关（默认关闭） |

**Wiki 索引启用后的额外配置**：

| 配置项 | 说明 |
| --- | --- |
| 提取粒度 | 聚焦 / 标准（默认）/ 详尽 |
| Wiki 内容生成要求 | 可选，最多 4000 字 |
| Wiki 提取重点 | 可选，最多 4000 字 |

### 2. 共享管理

共享管理用于将知识库共享到其他团队，实现跨团队协作。

> 提示：仅知识库创建者或团队管理员角色可操作共享。共享权限固定为编辑。

**操作步骤**：

1. 在左侧导航中点击「共享管理」。
2. 右侧显示「共享到团队」区域，从下拉框中选择目标团队。每个团队项显示头像、团队名称、角色、成员数和共享数。
3. 点击「共享」按钮完成共享。
4. 已共享的团队会显示在「已共享到」列表中，可点击删除按钮取消共享。

> 注意：创建模式下共享操作会被暂存，知识库创建成功后批量提交；编辑模式下直接调用 API 生效。

### 3. 高级配置 — 模型配置

模型配置定义知识库在文档处理和检索时使用的 AI 模型。

| 配置项 | 是否必填 | 说明 |
| --- | --- | --- |
| LLM 大语言模型 | **是** | 用于文档解析、问题生成等任务的主模型 |
| Embedding 嵌入模型 | RAG 启用时必填 | 用于将文本转换为向量的嵌入模型 |
| Wiki 合成模型 | Wiki 启用时显示 | 用于 Wiki 内容合成的模型 |

> 提示：创建时系统自动选择第一个默认模型或列表中第一个模型。编辑模式下若已有文件，Embedding 模型会被锁定不可修改。

---

### 4. 高级配置 — 向量存储

向量存储引擎决定知识库的向量索引存储方式。

| 配置项 | 说明 |
| --- | --- |
| 向量存储引擎 | 创建模式下可选，编辑模式下只读显示。选项分为「系统默认」和「用户自定义」两类 |

> 注意：向量存储引擎创建后不可更改，请根据数据规模和性能需求谨慎选择。

### 5. 高级配置 — FAQ 配置

FAQ 配置仅在知识库类型为「问答」时显示，控制问答对的索引方式。

**索引方式**：

| 选项 | 说明 | 建议场景 |
| --- | --- | --- |
| 仅标准问/相似问（默认） | 索引中只包含问题文本，语义匹配更精确 | FAQ 数量充足时优先选择 |
| 标准问+答案 | 索引中同时包含问题和答案，召回率更高但可能引入噪音 | FAQ 数量少或答案中有独特关键词时 |

**问题索引方式**：

| 选项 | 说明 | 建议场景 |
| --- | --- | --- |
| 合并索引 | 标准问和所有相似问拼成 1 条向量索引，节省存储空间 | FAQ 数量多、想节省存储时 |
| 分别索引（默认） | 标准问和每个相似问各自生成独立索引，检索更精确，支持增量更新 | 追求检索精度时 |

**示例**：标准问"如何重置密码？"，相似问["忘记密码怎么办", "密码找回方法"]

| 组合方式 | 生成的索引条数 | 索引内容 |
| --- | --- | --- |
| 合并索引 + 仅标准问 | 1 条 | `如何重置密码？忘记密码怎么办密码找回方法` |
| 合并索引 + 标准问+答案 | 1 条 | 上述 + 答案内容 |
| 分别索引 + 仅标准问 | 3 条 | 各自独立 |
| 分别索引 + 标准问+答案 | 3 条 | 各自 + 答案内容 |

### 6. 高级配置 — 解析引擎

解析引擎仅在文档类型知识库中显示，可按文件类型分组指定不同的解析引擎。

| 文件类型 | 扩展名 | 可选引擎 | 默认引擎 |
| --- | --- | --- | --- |
| PDF 文档 | .pdf | 内置、MinerU、MinerU Cloud、PaddleOCR-VL、PaddleOCR-VL Cloud、MarkItDown、OpenDataLoader | 内置 |
| Word 文档 | .docx/.doc | 内置、MinerU、MinerU Cloud、MarkItDown | 内置 |
| 演示文稿 | .pptx/.ppt | MinerU、MinerU Cloud、MarkItDown | MinerU Cloud |
| Excel 表格 | .xlsx/.xls | 内置、MarkItDown | 内置 |
| 电子书 | .epub | 内置 | 内置 |
| 网页归档 | .mhtml | 内置 | 内置 |
| CSV 文件 | .csv | simple、MarkItDown | simple |
| Markdown | .md/.markdown | 内置、simple、MarkItDown | 内置 |
| 纯文本 | .txt | simple | simple |
| JSON 文件 | .json | simple | simple |
| 图片 | .jpg/.jpeg/.png/.gif | 内置、simple、MinerU、MinerU Cloud、PaddleOCR-VL、PaddleOCR-VL Cloud | 内置 |
| 音频 | .mp3/.wav/.m4a/.flac/.ogg | simple | simple |
| HTM | .htm | 内置 | 内置 |
| HTML | .html | 内置 | 内置 |

**解析引擎说明**：

| 引擎 | 说明 |
| --- | --- |
| 内置（builtin） | DocReader 内置解析引擎，支持大多数文件格式，需 DocReader 服务已连接 |
| simple | Go 原生简单格式处理，无需外部服务，适用于文本类文件 |
| MinerU | MinerU 自建服务，需配置 mineru_endpoint |
| MinerU Cloud | MinerU 云 API，需配置 mineru_api_key |
| PaddleOCR-VL | PaddleOCR-VL 自建服务，需配置 paddleocr_vl_endpoint |
| PaddleOCR-VL Cloud | PaddleOCR-VL 云 API，需配置 paddleocr_vl_cloud_token |
| MarkItDown | 微软 MarkItDown 库解析引擎 |
| OpenDataLoader | OpenDataLoader PDF 版面分析，需 Java 11+ 环境 |

> 提示：大多数场景使用默认的内置引擎即可。PDF 文档如需更好的版面解析（表格、公式、复杂排版），可选 MinerU 或 PaddleOCR-VL。

### 7. 高级配置 — 图像处理（多模态）

图像处理配置用于启用多模态功能，让系统能够理解图片内容。

| 配置项 | 是否必填 | 说明 |
| --- | --- | --- |
| 多模态功能 | — | 开关，默认关闭；创建时如有 VLLM 内置模型则默认开启 |
| VLLM 视觉模型 | 启用时必填 | 用于图片内容理解的视觉语言模型 |
| 图片描述语言 | 否 | Chinese / English / Korean / Russian / 自动（默认） |
| 图片解析要求 | 否 | 最多 4000 字，可描述对图片解析的具体要求 |

### 9. 高级配置 — 分块设置

分块设置控制文档被切分为文本块的策略，直接影响检索精度。

| 配置项 | 说明 |
| --- | --- |
| 分块策略 | 自动（默认）/ heading（按标题切片）/ heuristic（结构感知）/ legacy（按长度切分）。选择 legacy 后高级选项禁用 |
| 分块大小 | 范围 100-4000，默认 512，步长 50 |
| 分块重叠 | 范围 0-500，默认 80，步长 20 |
| 分隔符 | 多选，可自定义创建。可选项：双换行 `\n\n`、单换行 `\n`、中文句号`。`、中文感叹号`！`、中文问号`？`、中文分号`；`、英文分号`;`、空格 |
| 父子分块 | 开关，默认开启。启用后检索时先匹配子块，回答时引用父块上下文 |
| 父块大小 | 父子分块启用时显示，范围 512-8192，默认 4096，步长 64 |
| 子块大小 | 父子分块启用时显示，范围 64-2048，默认 384，步长 32 |

**高级选项**（可展开/收缩）：

| 配置项 | 说明 |
| --- | --- |
| 每块 Token 上限 | 范围 0-8192，0 表示关闭，步长 64 |
| 语言提示 | 多选：自动检测 / 德语 / 英语 / 中文 |

> 提示：点击「测试分块效果」按钮可打开分块调试面板，预览当前配置下的分块结果。

### 10. 高级配置 — 知识图谱

知识图谱配置用于启用实体关系提取，构建文档间的结构化关联。

| 配置项 | 说明 |
| --- | --- |
| 启用实体关系提取 | 开关，默认关闭 |
| 额外提取要求 | 可选，最多 4000 字，注入领域特定的提取指导 |
| 关系类型 | 多选，可自定义创建。默认标签：Content / Culture / Person / Event / Time / Location / Work / Author / Relation / Attribute |
| 示例文本 | 最多 5000 字，带 AI 生成随机文本按钮 |
| 实体列表 | 动态添加，每个实体包含名称和属性列表 |
| 关系列表 | 动态添加，每条关系包含实体 1、关系类型、实体 2 |

**操作按钮**：

| 按钮 | 说明 |
| --- | --- |
| 开始提取 | 将示例文本发送给 LLM 提取实体和关系，结果自动填入列表 |
| 默认示例 | 填入一组示例数据（纯前端操作，不调用后端） |
| 清除示例 | 清空所有提取相关数据 |

> 前提条件：需要管理员权限、系统已启用图数据库（Neo4j）、知识库索引策略包含知识图谱。

### 11. 高级配置 — 高级设置

高级设置包含 AI 问题生成和表格元数据生成两项增强功能。

**AI 问题生成**：

| 配置项 | 说明 |
| --- | --- |
| AI 问题生成 | 开关，默认开启（仅 RAG 索引时显示） |
| 生成问题数量 | 范围 1-10，默认 3。数量越多召回率越高但处理时间更长 |
| 问题生成要求 | 可选，最多 4000 字，描述目标受众或问题风格 |

> 启用后，系统在文档解析阶段使用 LLM 为每个文本 chunk 自动生成问题并单独索引，用户提问时可直接匹配到这些问题，提高召回率。

**表格元数据生成要求**：

- 针对 CSV/Excel 表格文件，系统会使用 LLM 生成表格摘要和列描述。
- 提供业务上下文可帮助 LLM 生成更有针对性的摘要，例如"这是一份财务报表，请重点描述科目、金额和趋势"。
- 最多 4000 字。

#### 数据源管理

数据源管理仅在编辑模式下显示，用于将外部平台的文档自动同步到知识库中。

**支持的数据源类型**：

| 类型 | 说明 |
| --- | --- |
| 飞书 | 飞书文档、电子表格、多维表格 |
| Lark | 飞书国际版 |
| Notion | Notion 页面和数据库 |
| Confluence | Confluence 页面 |
| 语雀 | 语雀知识库 |
| GitHub | GitHub 仓库文档 |
| Google Drive | Google 文档、表格 |
| OneDrive | Microsoft 365 文档 |
| 钉钉 | 钉钉文档 |
| Web Crawler | 网站爬虫（Sitemap） |
| Slack | Slack 消息和文件 |
| Email | 邮件（IMAP） |
| RSS | RSS/Atom 订阅源 |

**飞书数据源配置步骤**：

1. **创建飞书应用**：登录飞书开放平台，创建企业自建应用，获取 App ID 和 App Secret。
2. **配置应用权限**：添加 `wiki:wiki:readonly`、`docx:document:readonly`、`sheets:spreadsheet:readonly` 权限。
3. **在系统中添加数据源**：选择类型为飞书，填写名称、App ID、App Secret，点击「测试连接」验证。
4. **选择同步资源**：验证成功后，选择需要同步的飞书空间或节点（支持多选）。
5. **配置同步设置**：设置同步策略（增量/全量）、同步计划（Cron 表达式）、冲突策略（覆盖/跳过）。

**数据源操作说明**：

| 操作 | 说明 |
| --- | --- |
| 创建 | 添加新的数据源连接 |
| 编辑 | 修改配置和同步设置 |
| 删除 | 软删除数据源（不会删除已同步的文档） |
| 触发同步 | 手动立即执行一次同步 |
| 暂停/恢复 | 临时停止或恢复定时同步 |
| 查看日志 | 查看同步历史记录 |

> 注意：数据源凭证采用 AES-256-GCM 加密存储。增量同步基于文档修改时间戳比较，仅同步有变更的文档。定时同步有防重叠机制，避免重复执行。

## 进阶用法

### 分块策略选择建议

| 场景 | 推荐策略 | 说明 |
| --- | --- | --- |
| 通用文档 | 自动 | 系统自动选择最佳策略 |
| 结构化文档（有清晰标题层级） | heading | 按标题切片，保留文档结构 |
| 复杂排版文档 | heuristic | 结构感知，适应复杂格式 |
| 兼容旧版 | legacy | 按固定长度切分，简单但可能切断语义 |

### 解析引擎选择建议

| 场景 | 推荐引擎 |
| --- | --- |
| 普通文档 | 内置（builtin）引擎 |
| 复杂表格/排版的 PDF | MinerU 或 PaddleOCR-VL |
| 扫描件/图片 PDF | PaddleOCR-VL（OCR 能力最强） |
| 纯文本 PDF | OpenDataLoader（速度快） |
| 无外部服务环境 | OpenDataLoader（本地运行） |

## 常见问题

### Q1：Embedding 模型为什么被锁定了？

编辑模式下，如果知识库已有导入的文件，Embedding 模型会被锁定不可修改。因为更换 Embedding 模型意味着需要重建所有向量索引，当前版本不支持自动迁移。如需更换，需要先删除所有文件再修改模型。

### Q2：向量存储引擎可以更换吗？

不可以。向量存储引擎在创建知识库后即锁定，无法更改。请在创建时根据数据规模和性能需求谨慎选择。

### Q3：父子分块有什么作用？

父子分块是一种提升检索精度的策略。开启后，系统在检索阶段使用较小的子块进行精确匹配，但在生成回答时引用包含更多上下文的父块。这样既保证了检索的精准度，又让回答拥有更完整的上下文信息。

### Q4：知识图谱提取需要什么条件？

知识图谱功能需要三个前提条件：① 管理员权限；② 系统已启用 Neo4j 图数据库；③ 知识库索引策略中包含知识图谱。如果条件不满足，相关功能区域会显示不可用提示。

### Q5：数据源同步失败怎么办？

点击数据源列表中的「查看日志」按钮，查看同步历史记录中的错误信息。常见原因包括：飞书应用权限不足、网络连接超时、文档格式不支持等。根据错误信息调整配置后，点击「触发同步」重新执行。

### Q6：分块大小设置多少合适？

默认的 512 适用于大多数场景。如果文档内容较短或需要更细粒度的检索，可适当调小（如 256-384）；如果文档内容较长且上下文连贯性强，可适当调大（如 1024-2048）。建议通过「测试分块效果」按钮预览后再确定。
